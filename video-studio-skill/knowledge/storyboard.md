# Storyboard intelligence

The storyboard sits between the script and the build. It turns each script beat into a frame the user can see and approve **before** any animation work is spent. A good storyboard makes the build mechanical: every decision about what appears, where, when and how has already been made.

## Completion contract

Produce two files in the project folder:

1. `storyboard.json` — machine-readable, one entry per frame (schema below). The build stage reads only this.
2. `storyboard.html` — a visual page for the user: one card per frame with a rough sketch in the style's colours, the narration, and what moves. Generated by `node <skill>/templates/storyboard.mjs <project>` from `storyboard.json`.

The storyboard is valid only if:
- every script beat maps to one or more frames, in order, with nothing invented that the script doesn't say;
- every frame follows the chosen style's section 11 "Storyboard frame spec" and section 5 "Scene grammar";
- every frame lists the assets it needs and where each comes from (built in code, starter kit, or a named free source);
- total estimated length is within ±10% of the script's target.

## The file shape

```json
{
  "title": "Why a $1.2M AI budget pays for itself",
  "style": "ray-dalio-principles",
  "palette": {"bg": "#2d4237", "ink": "#eef0e4", "accent": "#f6a800"},
  "worlds": {"green-chart": "#2d4237", "navy-story": "#18203d"},
  "frames": [ /* frame objects, below */ ]
}
```

Optional top-level `changes`: up to 5 short lines saying how the script was re-paced for the style (stage 2, step 4); the page shows them at the top.

Two optional frame fields beyond the schema below: `sketch_svg` (inner SVG markup for a 160x90 viewBox: a rough sketch you draw yourself; without it the page draws one box per element) and `risk` (one line, shown in red, when the frame is hard to build).

## The frame schema

```json
{
  "frame": "f03",
  "beat": "b02",
  "scene_type": "evidence-chart",
  "seconds_estimate": 7.5,
  "narration": "Every year, its customer service team answers about a hundred thousand questions.",
  "intent": "The scale of the problem: it's big and constant.",
  "world": "navy-story",
  "layout": "Building left third; 10x10 grid of speech bubbles right two thirds; title above grid.",
  "elements": [
    {"id": "building", "kind": "prop", "source": "code:svg", "note": "classical building, flag on top"},
    {"id": "bubbles", "kind": "icon-grid", "source": "code:svg", "count": 100},
    {"id": "title", "kind": "text", "text": "100,000 questions a year", "font": "display"}
  ],
  "motion": [
    {"at_word": "Every", "what": "building slides left, scales to 0.8", "dur": 0.6, "ease": "power3.inOut"},
    {"at_word": "answers", "what": "bubbles pop in, staggered 0.03s, random order", "dur": 3.2, "ease": "back.out(2.2)"},
    {"at_word": "thousand", "what": "title rises into view", "dur": 0.45, "ease": "power2.out"}
  ],
  "on_screen_text": ["100,000 questions a year"],
  "numbers": ["100,000"],
  "sfx": [{"at_word": "answers", "file": "pop-soft", "note": "light pops under the bubble stagger, -14 dB"}],
  "transition_out": {"type": "pan-left", "dur": 0.6},
  "notes_for_build": "Reuse the coin and bubble components from the kit."
}
```

Field rules:
- `scene_type` must be one of the style's scene grammar types.
- `source`: `code:svg` (drawn in code), `kit:<path>` (starter kit file), `lib:<source-name>:<url>` (downloaded from a free source in assets/sources.md), or `gen:<prompt>` (AI-generated; only if the style allows it and the user agreed).
- `at_word` uses an exact word from the narration, so timing can be placed once the voice exists.
- Keep `motion` to the moves that matter (3-6 per frame).

## How to storyboard (method)

0. **Style and brand come first** (stage 2 steps 1-4 in SKILL.md): the user picks them on `styles.html`, and the script is re-paced to the style before any frame is drawn.
1. **Read the style first:** scene grammar (§5), data treatment (§6), pacing (§8), frame spec (§11), do/don't (§12).
2. **Split beats into frames by idea, not by sentence.** A frame changes when the picture must change. In slow styles (Ray Dalio) one frame often holds 2-3 sentences; in fast styles (Varun Mayya) a sentence can need 2-3 frames.
3. **Pick the scene type** for each frame from the style's grammar. Vary them: don't use the same type more than 3 times in a row.
4. **Decide the one thing the eye should land on** in each frame, then place it first. Everything else is supporting.
5. **Tie every motion to a spoken word.** Visuals arrive on the word that names them, never before.
6. **Plan continuity:** what carries over between frames (same chart, same character, same colour coding for the same thing).
7. **List assets** and check each is available. If a person or object is needed that the kit can't supply, say so on the frame and offer a code-drawn alternative.
8. **Mark risks** on any frame that's hard to build (character acting, complex maps) so the user can simplify before approval.

## How the user reviews it

The storyboard page shows each frame as a card: number, sketch, narration, what moves, sound. The user replies in chat with either "approve" or per-frame notes, e.g. "f04: use a pie instead", "f07: cut". The agent updates `storyboard.json`, regenerates the page, and asks again. Only then does the build start.

## Sketch rules (storyboard.html)

Sketches are deliberately rough: coloured boxes, labels and simple shapes in the style's palette, at 16:9. They show composition and what's on screen, not final art. Each sketch is an inline SVG generated from `layout` and `elements`, so it costs nothing to redo.
